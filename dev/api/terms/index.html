Terms API Reference

This page documents all ERGM terms available in ERGM.jl.

Structural Terms

Terms based purely on network structure.

ERGM.Edges — Type
Edges <: StructuralTerm

The number of edges in the network (statnet edges, coefficient name "edges"). The most basic ERGM term, analogous to an intercept: alone it is the Bernoulli model, whose MLE is the logit of the density.

Example

using ERGM
net = load_dataset(:florentine_marriage)
compute(Edges(), net)                        # 20.0
round(coef(fit_ergm(net, Edges()))[1]; digits=4)   # -1.6094 == log(20/100)
source
ERGM.Mutual — Type
Mutual <: StructuralTerm

The number of mutual (reciprocated) dyads (statnet mutual). Directed networks only: requires_directed(Mutual()) == true, so a model with it on an undirected network is refused.

Example

using ERGM
net = network(3; directed=true)
add_edge!(net, 1, 2); add_edge!(net, 2, 1); add_edge!(net, 2, 3)
compute(Mutual(), net)              # 1.0
change_stat(Mutual(), net, 3, 2)    # 1.0 — 2→3 exists, so 3→2 would reciprocate it
source
ERGM.Triangle — Type
Triangle <: StructuralTerm

The number of triangles in the network.

For undirected networks this is the usual triangle count. For directed networks it follows the statnet triangle definition: the number of transitive triples plus the number of cyclic triples (ttriple + ctriple). Dyad-dependent: an MPLE fit with it prints the pseudo-likelihood caveat; prefer method=:mcmle. GWESP is the usual well-behaved alternative.

Example

using ERGM
net = load_dataset(:florentine_marriage)
compute(Triangle(), net)              # 3.0
change_stat(Triangle(), net, 6, 7)    # 1.0 — Barbadori and Guadagni share Medici
source
ERGM.Kstar — Type
Kstar <: StructuralTerm
Kstar(k)

The number of k-stars in the network (statnet's kstar(k), coefficient name "kstar<k>"). A k-star is a vertex together with k of its neighbours, so the statistic is Σᵥ C(deg(v), k).

Undirected networks only, as in R ergm (kstar "may not be used with networks with directed==TRUE"). On a directed network the model is refused at construction with an ArgumentError, and so are compute/change_stat; use OStar / IStar (statnet's ostar/istar) instead.

Changed in 0.2

Before 0.2 a directed network silently received out-stars under the label kstar<k>.

Fields

  • k::Int: Star size (number of spokes), at least 2

Example

using ERGM
net = load_dataset(:florentine_marriage)
compute(Kstar(2), net)     # 47.0 — Σᵥ C(deg(v), 2)
name(Kstar(3))             # "kstar3"
source
ERGM.OStar — Type
OStar <: StructuralTerm
OStar(k)

The number of out-k-stars in a directed network (statnet's ostar(k), coefficient name "ostar<k>"): a vertex together with k of its out-neighbours, so the statistic is Σᵥ C(outdeg(v), k). Directed networks only — on an undirected network use Kstar.

Adding the arc i→j only changes i's out-degree, so the change statistic is C(outdeg⁻(i)+1, k) − C(outdeg⁻(i), k) with outdeg⁻ the out-degree in the baseline state without the arc — an O(1) computation.

Fields

  • k::Int: Star size (number of out-spokes), at least 2

Example

using ERGM
net = network(3; directed=true)
add_edge!(net, 1, 2); add_edge!(net, 1, 3); add_edge!(net, 2, 3)
compute(OStar(2), net)     # 1.0 — only vertex 1 has out-degree 2
compute(IStar(2), net)     # 1.0 — only vertex 3 has in-degree 2
name(OStar(2))             # "ostar2"
source
ERGM.IStar — Type
IStar <: StructuralTerm
IStar(k)

The number of in-k-stars in a directed network (statnet's istar(k), coefficient name "istar<k>"): a vertex together with k of its in-neighbours, so the statistic is Σᵥ C(indeg(v), k). Directed networks only — on an undirected network use Kstar.

Adding the arc i→j only changes j's in-degree, so the change statistic is C(indeg⁻(j)+1, k) − C(indeg⁻(j), k) with indeg⁻ the in-degree in the baseline state without the arc — an O(1) computation.

Fields

  • k::Int: Star size (number of in-spokes), at least 2

Example

using ERGM
net = network(3; directed=true)
add_edge!(net, 1, 3); add_edge!(net, 2, 3)
compute(IStar(2), net)     # 1.0 — vertex 3 receives two arcs
compute(OStar(2), net)     # 0.0
name(IStar(3))             # "istar3"
source
ERGM.TwoPath — Type
TwoPath <: StructuralTerm

The number of two-paths in the network.

For directed networks: pairs of edges (h → v, v → k) with h ≠ k (statnet's twopath/m2star). For undirected networks: the number of 2-stars, Σᵥ C(deg(v), 2) — the same statistic as Kstar(2).

Example

using ERGM
net = load_dataset(:florentine_marriage)
compute(TwoPath(), net) == compute(Kstar(2), net)   # true (undirected)
compute(TwoPath(), net)                              # 47.0
source
ERGM.GWESP — Type
GWESP <: StructuralTerm
GWESP(decay=0.5; type=:OTP)

Geometrically Weighted Edgewise Shared Partners with fixed decay (statnet's gwesp(decay, fixed=TRUE)).

For undirected networks, shared partners of an edge (i,j) are the common neighbors of i and j; type is ignored.

For directed networks, type selects the shared-partner definition for each directed edge i→j, matching statnet's dgwesp types (the shared partner k is always distinct from i and j):

  • :OTP — outgoing two-path, k with i→k→j (statnet's default for directed gwesp; also the default here)
  • :ITP — incoming two-path, k with j→k→i
  • :OSP — outgoing shared partner, k with i→k and j→k
  • :ISP — incoming shared partner, k with k→i and k→j
  • :union — k adjacent to both i and j in either direction. This is not a statnet type; it preserves this package's historical (pre-0.2) directed GWESP behavior and is named "gwesp.union.fixed.<decay>" so it can never be confused with statnet's OTP-based "gwesp.fixed.<decay>".

The decay must be non-negative; GWESP(0.0) is statnet's gwesp(0, fixed=TRUE) — the number of edges with at least one shared partner. Coefficient names follow R's labels exactly: an integer-valued decay prints without a decimal point ("gwesp.fixed.0", "gwesp.fixed.1"), a fractional one as is ("gwesp.fixed.0.5").

The label depends on the network's directedness, as in R. On an undirected network the coefficient is "gwesp.fixed.<decay>" (whatever type, which is ignored there). On a directed network R ergm 4.12.0 names every type — the default included — "gwesp.<type>.fixed.<decay>" (gwesp.OTP.fixed.0.5), and so does ERGM.jl wherever the network is known: ERGMModel/fit_ergm (fit.model.formula.terms.names), summary_stats and the two-argument name(term, net). The one-argument name(term), which cannot see a network, returns the undirected label for :OTP and "gwesp.<type>.fixed.<decay>" for the other types; :union is always "gwesp.union.fixed.<decay>".

Fields

  • decay::Float64: Decay parameter, ≥ 0 (higher = less downweighting)
  • type::Symbol: Directed shared-partner type (see above)

Example

using ERGM
net = load_dataset(:florentine_marriage)
compute(GWESP(0.5), net)   # 8.3934... (statnet: summary(flomarriage ~ gwesp(0.5, fixed=TRUE)))
compute(GWESP(0.0), net)   # 8.0 — edges with ≥ 1 shared partner
name(GWESP(0.0))           # "gwesp.fixed.0"
name(GWESP(0.5), net)      # "gwesp.fixed.0.5" — undirected label
dnet = network(4; directed=true); add_edge!(dnet, 1, 2); add_edge!(dnet, 2, 3)
name(GWESP(0.5), dnet)     # "gwesp.OTP.fixed.0.5" — R's directed label
source
ERGM.GWDSP — Type
GWDSP <: StructuralTerm
GWDSP(decay=0.5; type=:OTP)

Geometrically Weighted Dyadwise Shared Partners with fixed decay (statnet's gwdsp(decay, fixed=TRUE)): the shared-partner analogue of GWESP summed over all dyads — tied or not — instead of over edges only.

For undirected networks the statistic sums eᵅ(1 − (1 − e⁻ᵅ)^dsp(i,j)) over all unordered dyads {i,j}, where dsp(i,j) is the number of common neighbors of i and j; type is ignored.

For directed networks, type selects the shared-partner definition, matching statnet's dgwdsp types (the shared partner k is always distinct from i and j). As in statnet's C implementation (ddsp), every directed type is summed over all ordered dyads (i, j), i ≠ j — including the symmetric :OSP/:ISP counts, so each unordered pair {i, j} contributes twice (R ergm 4.12.0 on samplike: gwdsp.OSP.fixed.0.5 = 316.085, gwdsp.ISP.fixed.0.5 = 229.136; pinned by the provenanced fixture):

  • :OTP — outgoing two-path, k with i→k→j (statnet's default for directed networks; also the default here). For dyadwise shared partners :OTP and :ITP yield the same statistic.
  • :ITP — incoming two-path, k with j→k→i
  • :OSP — outgoing shared partner, k with i→k and j→k (symmetric in i and j, hence counted for both (i, j) and (j, i))
  • :ISP — incoming shared partner, k with k→i and k→j (likewise)
  • :union — k adjacent to both i and j in either direction, summed over unordered dyads. This is not a statnet type; it mirrors GWESP's :union and is named "gwdsp.union.fixed.<decay>".

The decay must be non-negative; GWDSP(0.0) is statnet's gwdsp(0, fixed=TRUE) — the number of dyads with at least one shared partner. Coefficient names follow R's labels ("gwdsp.fixed.0", "gwdsp.fixed.0.5"), and — exactly as for GWESP — the label is direction-aware wherever the network is known: "gwdsp.fixed.<decay>" on an undirected network, "gwdsp.<type>.fixed.<decay>" (gwdsp.OTP.fixed.0.5 for the default) on a directed one, in ERGMModel, summary_stats and name(term, net).

Fields

  • decay::Float64: Decay parameter, ≥ 0 (higher = less downweighting)
  • type::Symbol: Directed shared-partner type (see above)

Example

using ERGM
net = load_dataset(:florentine_marriage)
compute(GWDSP(0.0), net)   # 43.0 — dyads with ≥ 1 shared partner
name(GWDSP(0.0))           # "gwdsp.fixed.0"
source
ERGM.GWDegree — Type
GWDegree <: StructuralTerm
GWDegree(decay=0.5)

Geometrically Weighted Degree distribution with fixed decay (statnet's gwdegree(decay, fixed=TRUE), coefficient name "gwdeg.fixed.<decay>" — R's label, with an integer-valued decay printed without a decimal point).

Undirected networks only, as in R ergm (gwdegree "may not be used with networks with directed==TRUE"). On a directed network the model is refused at construction with an ArgumentError, and so are compute/change_stat; use GWODegree / GWIDegree instead.

The decay must be non-negative; GWDegree(0.0) is statnet's gwdegree(0, fixed=TRUE) — the number of non-isolated vertices.

Changed in 0.2

Before 0.2 a directed network silently received the out-degree statistic under the label gwdegree.fixed.<decay>, and the undirected coefficient was labelled gwdegree.fixed.<decay> where R writes gwdeg.fixed.<decay>.

  • decay::Float64: Decay parameter, ≥ 0

Example

using ERGM
net = load_dataset(:florentine_marriage)
compute(GWDegree(0.0), net)   # 15.0 — every family but Pucci has a tie
name(GWDegree(0.5))           # "gwdeg.fixed.0.5"
name(GWDegree(1.0))           # "gwdeg.fixed.1"
source

ERGM.Degree — Type
Degree <: StructuralTerm
Degree(d)
Degree(ds)

The number of vertices with degree exactly d (statnet's degree(d), coefficient name "degree<d>"). Only defined for undirected networks, as in R ergm — use IDegree / ODegree for directed networks (the model is refused at construction otherwise, and so are compute/change_stat).

As in statnet, a vector (or range) of degrees is one term that expands into one statistic per degree when the model is built: Degree(0:2) in a term list becomes degree0, degree1, degree2 in the fit, exactly like a multi-level NodeFactor. The unexpanded multi-degree term is a specification, not a statistic — compute(Degree(0:2), net) throws; use summary_stats or build the model.

fit_ergm(net, [Edges(), Degree(0:2)])   # coefficients edges, degree0, degree1, degree2

Fields

  • degrees::Vector{Int}: The degree(s) counted

Example

using ERGM
net = load_dataset(:florentine_marriage)
compute(Degree(0), net)                    # 1.0 — Pucci is isolated
summary_stats(net, [Degree(0:2)])          # (degree0 = 1.0, degree1 = 4.0, degree2 = 2.0)
name(Degree(1))                            # "degree1"
Degree(0:2) == Degree([0, 1, 2])           # true
source

Nodal Attribute Terms

Terms incorporating vertex-level attributes.

ERGM.NodeFactor — Type
NodeFactor <: NodalTerm
NodeFactor(attr; levels=nothing, base=1, level=nothing)

Main effect of a categorical vertex attribute (R ergm's nodefactor): for each included attribute level, the number of times a vertex with that level appears as an endpoint of an edge. As in statnet, an edge within the level counts twice, and one statistic is produced per included level (named "nodefactor.<attr>.<level>"); the levels are resolved from the network at model construction, where the term expands into its per-level statistics.

Which levels are included follows statnet:

  • By default the first level is dropped (base=1): the levels are the sorted distinct attribute values, and the lowest acts as the reference category. Including all levels would make the term collinear with Edges.
  • base gives the indices (into the sorted levels) to drop; base=0 keeps every level.
  • levels gives the included attribute values explicitly, in order, overriding base.
  • level=x constructs a single-level term directly (one statistic, no expansion), equivalent to levels=[x].
Changed in 0.2

NodeFactor(attr) previously produced a single statistic counting the endpoint appearances of every vertex with the attribute — collinear with Edges by construction. It now matches statnet: one statistic per attribute level, with the first (sorted) level dropped as the reference. Pass base=0 to keep all levels.

Before expansion (e.g. compute on a term that has not been through model construction), a multi-level term evaluates to the sum of its per-level statistics.

Fields

  • attr::Symbol: Vertex attribute name
  • level::Any: Single level counted (nothing for a multi-level term)
  • levels::Union{Nothing, Vector{Any}}: Explicit included levels
  • base::Vector{Int}: Sorted-level indices dropped (default [1])

Example

using ERGM
net = load_dataset(:florentine_marriage)
rich = Dict(v => (w > 40 ? "rich" : "poor") for (v, w) in get_vertex_attribute(net, :wealth))
set_vertex_attribute!(net, :class, rich)
fit = fit_ergm(net, [Edges(), NodeFactor(:class)])
fit.model.formula.terms.names      # ["edges", "nodefactor.class.rich"] — "poor" is the reference
compute(NodeFactor(:class; level="rich"), net)   # 20.0 endpoint appearances
source
ERGM.NodeCov — Type
NodeCov <: NodalTerm
NodeCov(attr; transform=:none)

Main effect of a continuous vertex attribute (R ergm's nodecov): the sum of the attribute values of both endpoints over the edges, named "nodecov.<attr>".

The attribute must be set on every vertex: as in statnet (which refuses NA attribute values), ERGMModel throws an ArgumentError naming the term, the attribute and the vertices without a value, and a direct compute/change_stat on incomplete data throws rather than zero-filling.

Fields

  • attr::Symbol: Vertex attribute name
  • transform::Symbol: Optional transform of each vertex's value before summing — :none (default), :log (log(x + 1)) or :sqrt. Any other symbol is an ArgumentError (it used to fall back silently to :none).

Example

using ERGM
net = load_dataset(:florentine_marriage)
compute(NodeCov(:wealth), net)             # 2168.0
name(NodeCov(:wealth; transform=:log))     # "nodecov.wealth"
source
ERGM.NodeMatch — Type
NodeMatch <: NodalTerm
NodeMatch(attr; diff=false, level=nothing)

Homophily effect: the number of edges whose endpoints have matching values of the vertex attribute attr (R ergm's nodematch).

With diff=false (uniform homophily, the default) this is a single statistic counting all matched edges, named "nodematch.<attr>".

With diff=true (differential homophily, matching R's nodematch(attr, diff=TRUE)) there is one statistic per attribute level, each counting only the edges matched on that level and named "nodematch.<attr>.<level>". Since this package's term system is one-statistic-per-term (like NodeFactor), construct one NodeMatch per level:

levels = sort(unique(values(get_vertex_attribute(net, :group))))
terms = [NodeMatch(:group; diff=true, level=l) for l in levels]
Changed in 0.2

diff=true previously counted mismatched edges — a different model from R's nodematch(diff=TRUE) under the same keyword. That statistic is now available as NodeMismatch.

Fields

  • attr::Symbol: Vertex attribute name
  • diff::Bool: Differential (per-level) homophily as in R
  • level::Any: The attribute level counted (required when diff=true)

Example

using ERGM
net = load_dataset(:florentine_marriage)
rich = Dict(v => (w > 40 ? "rich" : "poor") for (v, w) in get_vertex_attribute(net, :wealth))
set_vertex_attribute!(net, :class, rich)
compute(NodeMatch(:class), net)                          # 10.0 within-class ties
levels = sort(unique(values(rich)))                      # ["poor", "rich"]
terms = [NodeMatch(:class; diff=true, level=l) for l in levels]
sum(compute(t, net) for t in terms)                      # 10.0
source
ERGM.NodeMismatch — Type
NodeMismatch <: NodalTerm
NodeMismatch(attr)

Heterophily effect: the number of edges whose endpoints have different (non-missing) values of the vertex attribute attr. Named "nodemismatch.<attr>".

This is the statistic that NodeMatch(attr; diff=true) computed before 0.2; it has no R ergm equivalent under the nodematch name (R's diff=TRUE is per-level homophily — see NodeMatch).

Fields

  • attr::Symbol: Vertex attribute name

Example

using ERGM
net = load_dataset(:florentine_marriage)
rich = Dict(v => (w > 40 ? "rich" : "poor") for (v, w) in get_vertex_attribute(net, :wealth))
set_vertex_attribute!(net, :class, rich)
compute(NodeMismatch(:class), net) + compute(NodeMatch(:class), net) == 20.0   # true
source
ERGM.NodeMix — Type
NodeMix <: NodalTerm
NodeMix(attr; levels=nothing, levels2=-1)
NodeMix(attr, l1, l2)

Mixing-matrix cell counts for a categorical vertex attribute (R ergm's nodemix): one statistic per mixing cell, counting the edges whose endpoint levels fall in that cell, named "mix.<attr>.<l1>.<l2>".

The cells follow statnet's level ordering. With sorted levels u₁ < u₂ < …:

  • undirected networks use the unordered cells (uᵢ, uⱼ) with i ≤ j, in column-major order: (u₁,u₁), (u₁,u₂), (u₂,u₂), (u₁,u₃), …
  • directed networks use all ordered (tail-level, head-level) cells in column-major order: (u₁,u₁), (u₂,u₁), …, (u₁,u₂), …

and statnet's reference handling: by default the first cell is dropped (levels2=-1), acting as the reference category. levels2 selects cells by index into the ordered cell list — all-negative values drop those cells, all-positive values keep exactly those cells (in the given order), and levels2=0 keeps every cell. levels restricts (and orders) the attribute levels used to build the cells.

Like NodeFactor, the cells are resolved from the network at model construction, where the term expands into its per-cell statistics; NodeMix(attr, l1, l2) constructs a single-cell term directly. Before expansion, a multi-cell term evaluates to the sum of its selected cells.

Fields

  • attr::Symbol: Vertex attribute name
  • l1::Any, l2::Any: The cell's levels (nothing for a multi-cell term); for directed networks l1 is the tail (sender) level and l2 the head (receiver) level
  • levels::Union{Nothing, Vector{Any}}: Levels used to build the cells
  • levels2::Vector{Int}: Cell selection (see above)

Example

using ERGM
net = load_dataset(:florentine_marriage)
rich = Dict(v => (w > 40 ? "rich" : "poor") for (v, w) in get_vertex_attribute(net, :wealth))
set_vertex_attribute!(net, :class, rich)
fit = fit_ergm(net, [Edges(), NodeMix(:class)])
fit.model.formula.terms.names   # ["edges", "mix.class.poor.rich", "mix.class.rich.rich"]
compute(NodeMix(:class, "poor", "rich"), net)   # 10.0 cross-class ties
source
ERGM.AbsDiff — Type
AbsDiff <: NodalTerm
AbsDiff(attr; pow=1)

Absolute difference in a continuous attribute between edge endpoints (R ergm's absdiff): Σ_edges |xᵢ − xⱼ|^pow, named "absdiff.<attr>" for pow = 1 and "absdiff<pow>.<attr>" otherwise (absdiff2.wealth, absdiff0.5.wealth — R's labels, so two powers of one attribute in a formula print distinct names; pinned by the provenanced fixture).

The attribute must be set on every vertex: as in statnet, ERGMModel throws an ArgumentError naming the vertices without a value, and a direct compute/change_stat on incomplete data throws rather than zero-filling.

Fields

  • attr::Symbol: Vertex attribute name
  • pow::Float64: Power to raise the difference to (default 1; any Real is accepted and stored as a Float64, so R's absdiff("wealth", pow=2) is AbsDiff(:wealth; pow=2))

Example

using ERGM
net = load_dataset(:florentine_marriage)
compute(AbsDiff(:wealth), net)     # 1146.0
compute(AbsDiff(:wealth; pow=2), net)   # 91570.0 (R: summary(flomarriage ~ absdiff("wealth", pow=2)))
name(AbsDiff(:wealth; pow=2))      # "absdiff2.wealth"
source

Dyadic Terms

Terms based on dyad-level covariates.

ERGM.EdgeCov — Type
EdgeCov <: DyadicTerm

Dyad-level covariate effect (statnet edgecov): the sum of the covariate over the edges present. Built from an n×n matrix (EdgeCov(M; name="edgecov"); undirected networks read the (min, max) entry) or from an edge attribute (EdgeCov(net, :attr)). Dyad-independent.

The matrix must be n×n for the network it is used on: ERGMModel/ fit_ergm, compute and change_stat all throw an ArgumentError naming the sizes otherwise (a matrix built for another network is the commonest edgecov slip, and a BoundsError would not say so).

Fields

  • covariate::Matrix{Float64}: n×n matrix of dyad covariates
  • name_str::String: Name for this term

Example

using ERGM
net = load_dataset(:florentine_marriage)
w = get_vertex_attribute(net, :wealth)
M = [Float64(abs(w[i] - w[j])) for i in 1:16, j in 1:16]      # wealth gap per dyad
term = EdgeCov(M; name="edgecov.wealthgap")
compute(term, net) == compute(AbsDiff(:wealth), net)          # true
name(term)                                                    # "edgecov.wealthgap"

Term Traits

The public protocol by which a term — ERGM.jl's own or a third party's — declares what it needs and where it belongs. ERGM.jl acts on the declarations when an ERGMModel is constructed: a term whose declared vertex/edge attributes are absent from the network, or whose direction requirement the network does not meet, is rejected with an ArgumentError instead of silently contributing an all-zero design column.

ERGM.required_vertex_attributes — Function
required_vertex_attributes(term::AbstractERGMTerm) -> Tuple{Vararg{Symbol}}

The vertex attributes the term needs on the network, as a tuple of symbols (empty for terms that read none — the default).

A term whose statistic reads a vertex attribute must declare it. ERGM.jl checks the declaration against list_vertex_attributes(net) when an ERGMModel is built and throws an ArgumentError if the attribute is absent, because the alternative is silent nonsense: get_vertex_attribute returns an empty Dict for an unknown attribute, so an undeclared attribute-based term would quietly evaluate to an all-zero design column and a meaningless coefficient.

Declared attributes are also what makes a term eligible for attribute materialization (dense typed snapshots; ERGM's own nodal terms only).

Example

struct Homophily <: AbstractERGMTerm
    attr::Symbol
end
ERGM.required_vertex_attributes(t::Homophily) = (t.attr,)

See also required_edge_attributes, requires_directed, is_dyad_dependent.

source
ERGM.required_edge_attributes — Function
required_edge_attributes(term::AbstractERGMTerm) -> Tuple{Vararg{Symbol}}

The edge (dyad) attributes the term needs on the network, as a tuple of symbols (empty by default). Validated against list_edge_attributes(net) at model construction exactly like required_vertex_attributes.

Declare an edge attribute only when its absence is an error. A term that falls back to a default weight for edges without the attribute (as ERGMUserterms.WeightedEdges does) genuinely does not require it and must not declare it — otherwise a perfectly meaningful model would be rejected.

None of ERGM.jl's built-in terms declare one: EdgeCov snapshots the dyadic covariate into a matrix at construction time, so by the time the model is built the attribute is no longer needed.

Example

using ERGM
required_edge_attributes(EdgeCov(zeros(3, 3)))        # ()
struct Weighted <: AbstractERGMTerm end
ERGM.required_edge_attributes(::Weighted) = (:weight,)
required_edge_attributes(Weighted())                   # (:weight,)
source
ERGM.requires_directed — Function
requires_directed(term::AbstractERGMTerm) -> Bool

Whether the term is only defined for directed networks (false by default). Model construction rejects such a term on an undirected network with an ArgumentError, as R ergm does: there its statistic would be a structural zero or a silent duplicate of another term, not a model.

Built-in terms declaring true: Mutual, IStar, OStar, IDegree, ODegree, GWIDegree, GWODegree. TERGM.jl declares it for Delrecip.

See also requires_undirected.

Example

using ERGM
requires_directed(Mutual())     # true
requires_directed(Edges())      # false
try
    ERGMModel(ERGMFormula([Mutual()]), load_dataset(:florentine_marriage))
catch e
    e isa ArgumentError           # true — refused on an undirected network
end
source
ERGM.requires_undirected — Function
requires_undirected(term::AbstractERGMTerm) -> Bool

Whether the term is only defined for undirected networks (false by default). Model construction rejects such a term on a directed network with an ArgumentError, pointing at the in-/out- variant to use instead.

Built-in terms declaring true, exactly the terms R ergm refuses on a directed network: Degree (use IDegree/ODegree), Kstar (use IStar/OStar) and GWDegree (use GWIDegree/GWODegree). These three also refuse a directed network in compute/change_stat themselves, so a caller bypassing ERGMModel (a variant lifting a term to a layer or a panel) cannot silently receive the out-degree statistic under the undirected label, as happened before 0.2.

See also requires_directed.

Example

using ERGM
requires_undirected(Kstar(2))     # true
requires_undirected(OStar(2))     # false — the directed counterpart
source

Two further traits complete the protocol:

  • is_dyad_dependent — whether the change statistic reads other dyads (conservative default true); it drives the pseudo-likelihood caveat and the MCMLE bridge reference.
  • Networks.supports_missing — whether the term's statistic honours the missing-dyad mask, i.e. is invariant to the face value of a dyad marked with set_missing_dyad! (default false, the honest answer for every built-in term: they count masked dyads at face value, and the principled missing-data treatment lives in the estimator — see mple).

A third-party term declares them by adding methods:

using ERGM
using Networks

struct RichClub <: AbstractERGMTerm
    attr::Symbol
end

ERGM.name(t::RichClub) = "richclub.$(t.attr)"
# ... plus compute(t, net) and change_stat(t, net, i, j)

ERGM.required_vertex_attributes(t::RichClub) = (t.attr,)
ERGM.requires_directed(::RichClub)           = true
ERGM.is_dyad_dependent(::RichClub)           = true
Networks.supports_missing(::RichClub)        = false

ERGMUserterms.validate_term exercises every one of these declarations against a network; ERGMUserterms.jl/examples/MyTermPackage is a complete package template built on them.

Pre-0.2 private names

The traits were internal before v0.2 (ERGM._vertex_attribute, ERGM._requires_directed, ERGM._requires_undirected). The private names remain as aliases of the same generics, so downstream methods declared against them (TERGM.jl's ERGM._requires_directed(::Delrecip) = true) keep working, but new code should use the public names.
